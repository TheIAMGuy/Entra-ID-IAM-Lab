# IAM Glossary: Identity and Access Management Terminology

Comprehensive glossary of 100+ IAM terms, acronyms, and concepts used throughout this knowledge base.

## Core Identity Terms

**Identity**: Representation of a person, system, or entity in digital form. Example: user account john.smith@company.com

**User Account**: Digital representation of a person with credentials (username, password) for system access.

**Credential**: Something that proves identity: password, certificate, token, biometric.

**UPN (User Principal Name)**: Unique identifier in directory (Azure AD format: user@domain.com)

**SID (Security Identifier)**: Unique identifier for user/group in Active Directory. Used internally by Windows.

**Directory Service**: System storing identities and their attributes (Active Directory, Azure AD, LDAP)

## Authentication Terms

**Authentication**: Verifying someone's identity. "You are who you claim to be."

**Authorization**: Granting permission to do something. "You can access this resource."

**Factor**: Element of multi-factor authentication (something you know, have, are, or do)

**MFA (Multi-Factor Authentication)**: Requiring 2+ factors to authenticate. Example: password + phone code

**Passwordless**: Authentication without password. Examples: FIDO2 keys, biometric, Windows Hello

**FIDO2 (Fast Identity Online)**: Open standard for phishing-resistant authentication using hardware keys

**Biometric**: Authentication using physical characteristics (fingerprint, face, iris)

**TOTP (Time-based One-Time Password)**: Temporary code generated by authenticator app (changes every 30 seconds)

**Hardware Security Key**: Physical device (USB, NFC) for authentication and cryptography

## Access Control Terms

**RBAC (Role-Based Access Control)**: Granting access based on assigned role (e.g., "Manager" role)

**ABAC (Attribute-Based Access Control)**: Granting access based on attributes (e.g., Department="Finance" + Security Clearance="Secret")

**Privilege**: Permission to perform an action or access a resource

**Least Privilege**: Principle of granting minimal necessary permissions

**PAM (Privileged Access Management)**: Managing high-privilege access (admin, root accounts)

**JIT (Just-In-Time Access)**: Granting temporary admin access for specific time period (e.g., 2 hours)

**SoD (Segregation of Duties)**: Preventing one person from having conflicting permissions (e.g., can't both approve and execute payment)

**ACL (Access Control List)**: List of which users/groups have access to a resource

**Entitlement**: Permission or access right assigned to a user

## Provisioning Terms

**Provisioning**: Creating and configuring user account and access rights

**Joiner**: New employee onboarding process

**Mover**: Employee transfer (role change, department change)

**Leaver**: Employee offboarding process

**Deprovisioning**: Removing user account and access rights

**Lifecycle**: Full journey from creation to deletion (joiner → mover → leaver)

**Attestation**: Confirming that access is still appropriate/needed

**Recertification**: Periodic review that access is still justified

## Standards & Protocols

**SAML (Security Assertion Markup Language)**: XML-based standard for single sign-on (common in enterprise)

**OAuth 2.0**: Authorization protocol for delegated access (common for APIs and third-party apps)

**OIDC (OpenID Connect)**: Identity layer on top of OAuth 2.0 (adds identity information to OAuth)

**SCIM (System for Cross-domain Identity Management)**: API standard for user provisioning

**LDAP (Lightweight Directory Access Protocol)**: Protocol for querying and modifying directory services

**JWT (JSON Web Token)**: Self-contained token with claims, used for stateless authentication

**SPIFFE (Secure Production Identity Framework for Everyone)**: Standard for workload identity

**WebAuthn**: Web standard for phishing-resistant authentication using FIDO2

**PKI (Public Key Infrastructure)**: System for managing digital certificates

## Cloud & Hybrid Terms

**Azure AD (Entra ID)**: Microsoft's cloud identity service (rebranded to Microsoft Entra ID)

**Hybrid Identity**: Running identity in both on-premises (AD) and cloud (Azure AD)

**Azure AD Connect**: Tool that synchronizes on-premises AD to Azure AD

**Cloud Sync**: Azure AD Connect Cloud Sync, modern cloud-based sync agent

**Federation**: Trusting another organization's identity (SSO across organizations)

**Trust Relationship**: Established connection between identity providers for authentication

**Multi-Cloud**: Using identity across multiple cloud providers (AWS, Azure, GCP)

**Workload Identity**: Identity for applications/services (not humans)

**Service Principal**: Application registration in Azure AD representing a workload

**Managed Identity**: Azure feature for automatic credential management for workloads

## Governance & Compliance Terms

**IGA (Identity Governance & Administration)**: Platform and processes for access governance

**GRC (Governance, Risk & Compliance)**: Framework for managing governance, risks, and compliance

**Access Review**: Periodic audit that users have appropriate access

**Compliance Framework**: Set of standards and requirements (HIPAA, GDPR, PCI, etc.)

**Control**: Technical or operational measure to meet a compliance requirement

**Risk Scoring**: Numeric assessment of likelihood and impact of identity risk

**Anomaly Detection**: ML-based identification of unusual behavior

**UEBA (User and Entity Behavior Analytics)**: ML analysis of user and system behavior

**Zero Trust**: Security model assuming breach and verifying every access request

**IVIP (Identity Verification Intelligence Platform)**: Gartner category combining identity analytics and risk intelligence

## Data Quality Terms

**Completeness**: Percentage of required attributes populated (e.g., 99% of users have email)

**Accuracy**: Percentage of attributes with correct values

**Consistency**: Attributes match across systems (HR system vs. AD vs. applications)

**Timeliness**: Data current as of today (not stale)

**Attribute**: Property of a user (email, department, job title, etc.)

**Master Data**: Single source of truth for user information (usually HR system)

**Data Sync**: Synchronization of data between systems

**Data Quality Score**: Overall metric combining completeness, accuracy, consistency, timeliness

## Incident & Risk Terms

**Compromise**: When attacker gains unauthorized access to account

**Breach**: Unauthorized access to data resulting in potential data loss

**Incident**: Security event requiring investigation and response

**MTTD (Mean Time To Detect)**: Average time from incident start to detection

**MTTR (Mean Time To Respond)**: Average time from detection to containment

**Forensics**: Investigation of incident to determine scope, impact, cause

**Remediation**: Fix or mitigation of security issue

**Rollback**: Reverting changes to previous known good state

**Insider Threat**: Threat from authorized user with legitimate access

## Process Terms

**Workflow**: Automated sequence of steps (e.g., access request → approval → provisioning)

**Approval**: Authorization by manager to grant access

**Policy**: Rule governing how identity/access is managed

**SLA (Service Level Agreement)**: Target performance commitment (e.g., "password reset within 4 hours")

**KPI (Key Performance Indicator)**: Metric measuring program health (e.g., "onboarding time <1 day")

**Metric**: Measurable value tracking program performance

**Dashboard**: Visual display of metrics and status

**Report**: Document summarizing metrics, compliance, or findings

## Security Model Terms

**Defense in Depth**: Multiple layers of security controls

**Principle of Least Privilege**: Grant minimum necessary permissions

**Assume Breach**: Security model assuming attacker is inside network

**Implicit Trust**: Trust devices/users on corporate network

**Explicit Verification**: Verify every access request (Zero Trust)

**Continuous Verification**: Ongoing assessment of trust

**Adaptive Security**: Security posture that adapts based on risk

**Defense Against Attacks**: Protections against common attack vectors (phishing, credential theft, etc.)

## Technology Stack Terms

**On-Premises (On-Prem)**: Systems running in organization's own data center

**Cloud**: Systems running at cloud provider (AWS, Azure, GCP)

**Hybrid**: Mix of on-premises and cloud

**SaaS (Software as a Service)**: Cloud-hosted application (Salesforce, Office 365)

**API (Application Programming Interface)**: Interface for programmatic communication between systems

**Middleware**: Software connecting two or more systems

**Connector**: Pre-built integration component (e.g., Azure AD → Salesforce connector)

**Tenant**: Isolated instance of cloud service for organization

## Framework Terms

**NIST (National Institute of Standards & Technology)**: US government agency providing cybersecurity standards

**NIST CSF (Cybersecurity Framework)**: Five-function framework (Identify, Protect, Detect, Respond, Recover)

**Gartner**: Research firm providing industry analysis and recommendations

**ISO 27001**: International standard for information security management

**HIPAA**: US healthcare privacy and security regulation

**GDPR**: EU General Data Protection Regulation

**PCI DSS**: Payment Card Industry Data Security Standard

**SOC 2**: Service Organization Control framework for service providers

**FedRAMP**: Federal Risk and Authorization Management Program

## Measurement Terms

**Maturity Level**: Assessment of organizational capability (1-5 scale)

**Baseline**: Current state measurement before improvement

**Target**: Desired future state

**Gap**: Difference between baseline and target

**ROI (Return on Investment)**: Financial return from investment

**Cost per User**: Annual IAM cost divided by number of users

**Automation Rate**: Percentage of processes that are automated

**Adoption Rate**: Percentage of users/systems using a capability
